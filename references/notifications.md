# 飞书通知：人工介入与最终结果

默认关闭，不读取 super-engineer 的凭证，不自动创建机器人。npm 安装钩子及 Agent 注册会自动补齐缺失的本机模板，已有配置不覆盖；--ignore-scripts 会跳过安装钩子，注册时仍会补齐。用户在本机 `~/.code2knowledge/config.yml` 配置（建议目录权限 700、文件权限 600，不提交 Git）：

```yaml
notification:
  feishu:
    enabled: false
    webhook_url: ""
    secret: "" # 机器人开启签名校验时填写
```

启用时填入自己的飞书/Lark 自定义机器人 webhook，改 enabled 为 true。配置启用即表示授权将本任务摘要发往该机器人所在会话；通知包含任务标识和本机输出位置，不发送源码、文档正文或原始 Git 错误。不要自动沿用其他 skill 的通知配置。支持官方 open.feishu.cn / open.larksuite.com webhook。

## 人工介入

仅在确实必须停止、等待用户处理时发送，如选定分支同步失败、转换依赖安装受阻、必要资料不可读。普通向导提问和可自动修复的校验错误不发送。Agent 将如下 JSON 写入工作区临时文件，然后调用：

```json
{
  "event": "intervention",
  "task": "稳定的向导 ID 或 run 绝对路径",
  "summary": "订单中心 / 退款：master 同步失败，需要人工处理",
  "details": ["服务：order-core；步骤：快进拉取", "原因：本地分支与远程分叉", "请保留本地提交，人工处理分支后回复继续"]
}
```

```bash
node "$SKILL/scripts/knowledge.mjs" notify --workspace "$WORKSPACE" --input "$WORKSPACE/notification-input.json"
```

task 使用稳定标识，同一次阻塞重试时保持摘要一致；恢复后新的阻塞需包含新的阶段/来源版本以区分事件。只发简要原因和下一步，不发送原始异常、凭证、私有 URL 或材料内容。通知后仍在当前会话明确请求人工介入，不能把通知当作用户回复，也不能自行继续。

## 最终结果

由 exportRun 在重新校验并导出成功后自动发送，Agent 不得提前手写 completed 通知。包含业务域、导出结果、本机输出位置、产物指纹及“业务仍待审核”。代码核验范围和测试限制以交付报告为准，不声称全部实现已验证。仅生成骨架、校验失败、只准备原料不会发送完成通知。

## 记录和失败

记录在 `<工作区>/notifications/<事件指纹>.json`。只有 status=sent 才表示飞书接口确认成功；skipped 表示未配置或关闭，failed 表示发送/配置异常。相同任务与事件内容已发送则跳过，导出内容变化会生成新完成事件；并发发送通过锁文件避免重复。失败可在人工排查后重试，未自动重试以免刷屏。网络超时存在消息已到达但本机未确认的可能，不能保证绝对一次投递。进程异常退出遗留 .lock 时，确认无发送进程后人工移除再重试。

通知失败不覆盖真实导出或阻塞状态，Agent 应在会话说明发送失败；如果记录写入失败，只能报告未确认，不能声称已通知。不提供在线产物托管，本机路径不是飞书可访问链接。

测试隔离：node:test 环境及其 CLI 子进程禁止真实通知传输，不读取本机通知配置；通知单测仅使用模拟传输。设置 C2K_NOTIFICATIONS_DISABLED=1 也可关闭真实发送。人工介入防重忽略每次变化的检查记录路径，同一仓库及同一阻塞内容只发送一次。

卡片样式：使用飞书 interactive 卡片，人工介入为橙色标题、完成为绿色标题，采用加粗分组标题与项目列表，依次展示任务摘要、任务结果/阻塞说明、交付位置/排查记录和下一步；移除双栏及分隔线，任务和路径使用代码样式。材料插入 Markdown 前转义，避免触发提及或格式注入。测试卡片必须醒目标记【测试】，真实发送前明确告知接收机器人和数量；自动化测试保持模拟传输隔离。
