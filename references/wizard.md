# 轻量选择向导与决策协议

## 提问方式

常规选择必须调用宿主 Agent 可用的结构化提问工具，不另外启动网页或终端问卷。此要求贯穿所有选择步骤，尤其包括最后的导出位置；普通消息中的编号列表不等于结构化选择。前面已使用交互选择时，后续必须沿用，不能因目录较长、候选只有两项或接近结束而改成“回复编号”。

优先单选：第一项给出有依据的推荐答案，保留自定义答案入口；宿主原生支持自由输入时使用原生入口，不再添加重复的“其他”项。宿主支持多选且问题确实需要多选时才用多选。选择自定义后，仅补问实际缺失的信息；名称、边界有可靠候选时同样先选择，无可靠候选时才直接收集文本，不能虚构推荐。

按宿主实际能力选工具，例如 Claude 的 AskUserQuestion、Codex 可用的 request_user_input_async；request_user_input 只在当前模式允许时使用。不能把某个工具在当前模式不可用等同于全部提问工具不可用，应先使用其他已提供且适用的结构化工具。仅在没有可用工具、工具明确受限或调用失败且无可用替代时，才列出编号选项并停止等待，并简述实际降级原因。不得假称调用了工具。仅推荐，不代用户选择；用户已经明确表达的选项直接沿用。

每轮最多一个主题、2–3 个主要候选。候选多时先显示最近项并允许查看其余；内部 ID、时间戳目录和 JSON 不要求用户填写。显示中心名、域名、简短状态、原料日期与服务名，以区分候选。

## 启动与发现

先运行 `discover`，只读取指定工作区。默认 `<任务目录>/.code2knowledge`；用户指定旧工作区或 run 路径时使用其工作区，不搜索整个主目录。

裸启动的第一条可交互问题来自实际数据：

| 已发现数据 | 提供的选择 |
| --- | --- |
| 有未完成任务/未填完向导 | 继续上次任务、复用共享原料（存在时）、新建 |
| 只有共享原料 | 复用共享原料、新建 |
| 没有历史 | 跳过操作菜单，直接收集新建必要信息 |

`discover.runs` 只包含未导出的任务，`wizards` 为未启动的问答检查点。已导出的任务通过原料在新域中复用；明确要更新已有域时可用 `runs` 查全部任务。读不到或损坏的记录不伪装成已完成，按需说明忽略了无效记录。

用户明确说“复用订单中心原料整理退款”，直接匹配中心/原料，不再问操作类型。用户给齐中心、仓库、域名、边界说明和导出位置时，若存在唯一匹配且版本核验通过的原料，可以直接复用，不再要求用户选择纯技术性的准备方式。用户明确给定 run 或 wizard 时直接恢复。不能仅凭启动词自动选定某个旧任务。

## 三条常用路径

### 继续上次任务

- 选择“继续”后，若总共只有一个候选直接使用，多个候选让用户选任务名，不让用户输入 run 路径。
- 未填完的向导：读 `wizard --wizard ID`，仅补 `missingFields`。
- 已有 run：读取 run、计划、evidence 和版本。已校验则继续导出；校验失败则定位问题；草稿/分析阶段接着分析。不要因 `wizard.status=started` 就当作知识库已完成。
- 不重复问中心、仓库、范围和输出目录；用户要求调整时再补问。

### 复用共享原料，整理业务域

- 原料候选显示如“订单中心 · order-api、order-core · 11月4日”。多个中心先按中心选择，只有一个中心或版本时不叠加重复菜单。
- 选择原料后带入中心、仓库、资料和上下文模式。命名业务域时可列出该中心已有域供更新，并允许用户输入新域名称。已有域的范围在用户选择“沿用范围”或明确要求更新同一范围后才沿用，不能把别的域范围自动带过来。
- 新域名称没有可靠候选时直接问“这次整理哪个业务域？”，不要为凑选择题虚构企业业务域。
- 业务域名、边界说明和导出位置按下方“三项业务域设置”逐项引导。复用仅带入原料信息，不能替用户决定新业务域边界或导出位置。
- 原料版本检查失败，给出“刷新当前原料 / 选择其他原料”。刷新时沿用中心、仓库和已填域名/范围，将向导 intent 改为 `new`，不用重填。补充资料有变化也刷新。

### 新建中心或共享原料

- 已有中心可选或自定义新中心；没有候选时先问业务中心。业务域名独立作为下一项引导；用户已一次提供“订单中心 / 退款”时拆分记录，不重复提问。不能强迫用户确认 Agent 自动推断的名称。
- 当前目录是仓库时提供“使用当前仓库（推荐） / 添加或选择其他仓库”。选择前者就记录当前绝对路径，不再问路径。用户已有路径时直接使用。只有 docs 的任务可以不提供代码仓库。
- 业务域名、业务域边界说明、知识库导出位置按下节引导；用户已明确提供某项则跳过该项。
- 确定仓库后，按下方“文档资料选择”显式询问是否添加资料；资料选择和知识库导出位置都不能当作可选技术参数而跳过。其他技术参数不逐项追问。
- 用户明确只要准备共享原料时使用 `material` 意图，跳过域名和业务范围；不强制额外走一遍业务域创建。

## 文档资料选择（新建原料，包括仅准备原料）

确定仓库后、调用 wizard-start 前，通过宿主结构化提问工具询问：“是否添加 PRD、ERD 等文档资料参与分析？”遵守选择优先规则，提供：

- **不添加，仅分析代码**：没有文档线索时推荐；保存 `answers.rawDocsDir: ""`。
- **添加文档资料**：用户已提到 PRD、ERD 或其他相关资料但未给路径时推荐；选择后仅补问本地资料目录，保存绝对路径到 `answers.rawDocsDir`。没有代码仓库时不能选择仅分析代码，直接收集资料目录。

说明可加入 PRD、ERD、业务规则、接口说明和数据库设计；文档用于提取业务意图并与源码交叉核验，不能单凭文档认定代码已实现。Markdown、TXT、CSV、YAML、JSON 可直接纳入；Word、PDF、Excel、PPT、HTML 需 MarkItDown 转换。图片型 ERD、扫描 PDF 应先整理为可读文本；在线链接需先获取授权并下载到本地，不把 URL 当成本地目录。

选择添加需转换的文档时，告知将检查并按需配套安装 MarkItDown（Python/pip，非 npm 依赖）；安装和验证遵循 execution.md。默认代码打包所需 Repomix 由 npm/npx 首次下载，也需提前告知。

用户已经给出目录或明确不添加时直接保存，不重复询问。用户选择添加但路径未齐全时保持等待，不能按默认空值继续。`missingFields` 在未回答时返回 rawDocsDir；默认不再填入空字符串，必须显式保存用户选择。底层创建原料同样拒绝缺省 rawDocsDir。恢复未启动向导时根据已有问答判断是否已完成选择，不重复问已回答项。开始前摘要同时展示资料目录或“无补充资料”。

复用原料或继续任务时展示已有资料并沿用，不强制重新提问；用户要求新增或替换资料时保留原料不可变，使用同一向导切换 `intent: new`、更新 `rawDocsDir` 并刷新原料，保留已填中心、仓库和业务域设置。

## 三项业务域设置（新建和复用均适用）

这三项对应原 Web 的“业务域名、业务域边界说明、知识资产导出目录”和 CLI 的 `--domain / --scope / --output`。已经给出的信息不重复问；未给出时每轮只引导一项。

### 1. 业务域名

提问：“这次要整理哪个业务域？”有该中心已有域时展示名称供更新，允许自行输入新名。没有可靠候选时提供“例如退款、订单履约”的格式示例，仅作为输入帮助，不代表自动划定业务域。中文作为展示名称保存到 `answers.domainName`，目录使用 `answers.domainSlug`。中心同理使用 `productName / productSlug`。

名称选项同时展示英文目录标识，如“退款（refund）”“订单履约（order-fulfillment）”，选择后一起保存。用户只给中文名时，由 Agent 推荐有业务含义的英文标识，提供“采用建议 / 自定义标识”，不要求用户理解 slug 或翻译英文。用户已给英文名或名称和标识时不重复问；纯英文名称可自动规范为小写连字符形式。复用已有中心或更新已有域必须沿用记录中的标识，不能根据中文名重新生成。

中心和域目录标识仅允许小写英文字母、数字及单连字符（例如 `order-center`、`refund`）；不能含中文、空格、点或下划线，也不能把中文删除后用残余字符凑标识。名称与英文标识未齐全时保持收集状态，不开始任务。

### 2. 业务域边界说明

提问：“这个业务域包含哪些流程，明确不包含哪些相邻业务？”优先基于用户已有描述给出具体边界草案，并提供“采用这份边界 / 修改边界”。例如退款域草案：

> 包含退款申请、审核和原路退回，以及相关状态、金额规则与异常处理；不包含售后换货，订单支付只保留必要依赖。

这是候选文本，必须用户选择后才能使用。没有足够依据提出具体草案时，直接请用户简述覆盖范围与排除项。不要用“全部主流程”“相关功能”等泛化文字替代明确边界；相邻域不扩写为本次主知识。用户已经提供清楚的范围时直接保存为 `answers.domainScope`。

### 3. 知识库导出位置

提问：“知识库导出到哪里？”必须通过宿主结构化提问工具显示以下单选，不能只在消息中列出两项让用户回复编号（仅上述工具不可用情形允许降级）：

- **当前任务目录（推荐）**：展示 `<任务目录>/code-knowledge/<product-slug>/<domain-slug>/` 的实际完整路径。
- **自定义目录**：用户输入导出根目录，再展示追加 `code-knowledge/<product-slug>/<domain-slug>/` 后的最终路径，避免把根目录当成最终目录。

选择当前目录后，将任务启动目录显式写入 `answers.outputRootDir`；自定义则记录用户输入并解析相对路径。不能因发现接口给出默认推荐值就视为用户已选择。用户回复“默认”可视为选择当前目录。自定义路径已明确时不再问一次选择题。

`wizard` 返回 `exportDirPreview`，开始前用它连同域名和边界说明展示摘要。资料与中间产物仍保留在工作区，不因修改导出位置而移动。用户仅准备原料时无需业务域设置；继续已有任务则沿用保存的设置并展示摘要，不重复提问。

## 启动前分支检查

文档资料选择和必填设置齐全后、wizard-start 前，按 execution.md 的 master 检查协议检查全部依赖服务：自动切换 master、从 origin 快进拉取、核对 HEAD 与 origin/master 一致。该步骤不新增选择题或开始确认。任何失败立即停止并请求人工介入，不能忽略错误继续逆向。复用和续跑同样执行；代码更新使原料过期时按刷新流程处理，不能改写历史版本证据。

## 持久化与推进

`wizard` 只保存用户已给出的答案，不提取代码。每个向导有独立 `wizardId`，存于 `.code2knowledge/wizards/`，互不覆盖。`collecting → ready → started` 只是参数收集状态，分析进度仍由 `run.json`、计划和 evidence 表达。

用户更换域名且没有同时给出新范围时，清空原范围并重新询问范围选择，不能沿用其他域的范围。更换中心或域名时也清空旧标识，重新确定对应英文标识；用户明确选择已有记录或同时给出标识时沿用。收到答案后保存；`missingFields` 为空且文档资料选择已完成时无需重复确认，显示业务域名、边界说明和 exportDirPreview 的简短摘要、完成分支检查后执行 `wizard-start`，直接进入分析。`wizard-start` 会关联生成的 run/material；中断后再次调用返回同一任务。不要再额外调用 `prepare` 造成重复任务。

同名导出目录已存在时，只有用户明确选择更新该域或已授权更新才允许覆盖；否则询问“更新已有业务域 / 另取名称”。选更新后不重复问相同授权。普通只读发现、版本检查和阶段推进不额外增加确认。
